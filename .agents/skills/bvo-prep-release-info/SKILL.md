# Подготовка информации о релизе BvO Another

Применяй только в BvO Another. Используй существующий [prep-release-info.py](../../../toolkit/prep-release-info/prep-release-info.py): он меняет исходники напрямую, отдельно от билдера. Нужен Python 3.

## Входные данные и запуск

Получить от пользователя номер версии без `#` и дату в формате `DD.MM.YYYY`. Если значение не задано, уточнить его. Значения в примере не являются значениями по умолчанию.

Из корня репозитория выполнить, подставив согласованные версию и дату:

```powershell
python toolkit/prep-release-info/prep-release-info.py 1.5 12.10.2026
```

Скрипт точечно заменяет существующие значения после `Rossoliny ` или `Release: ` и после `Date: `. Базовая версия `v1.1a`, остальные тексты, цветовые коды и переносы сохраняются.

| Файл в `w3x-content/` | Целевые места |
| --- | --- |
| `war3map.w3i` | Название и описание карты, заголовок и подзаголовок загрузочного экрана; поддерживается формат W3I 25. |
| `scripts/war3map.j` | Строковое имя в `SetMapName`, описание в `SetMapDescription`, тексты INFO `Contacts` и `Latest Version`. |
| `war3mapskin.txt` | `UPKEEP_NONE` и `RESOURCE_UBERTIP_UPKEEP`. |
| `war3map.wts` | `STRING 3`, `4654`, `5692`, `6743`, `6747`. |

## Отсутствующие строки

Скрипт проверяет все четыре файла до первой записи. Если целевое поле отсутствует, неоднозначно или не содержит нужного значения, он завершается с ошибкой без записи.

Сообщить конкретное неподготовленное место. Если пользователь просит инструкции, объяснить, где нужны существующее название с `Rossoliny 1.4` и строка `Release: 1.4 - Date: 12.10.2026`; версия и дата здесь лишь пример. Переносы задаются обычными строками в WTS/W3I, `\n` в строках JASS и `|n` в тултипе skin.

В `SetMapName` требуется строковый литерал с версией. Не добавлять версию в общие строки режима игры или заголовка таблицы счёта вместо этого литерала. Однократное добавление отсутствующих строк в исходники требует отдельного согласованного запроса; скрипт их не создаёт.

## Проверка результата

Проверить exit code и изменения четырёх целевых файлов относительно состояния перед запуском. Допустимы только переданные версия и дата; уже имевшиеся правки сохраняются. Для бинарного W3I проверять значения целевых полей и сохранность остальных байтов, а не полагаться только на `git diff`.

Сообщить использованные версию, дату и результат. Подготовка информации не запускает сборку, commit или публикацию. Когда сборка также входит в запрос пользователя, после успешной подготовки применить `bvo-build` отдельно.
