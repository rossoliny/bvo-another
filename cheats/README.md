# Читы, отладка и тестирование BvO

**Статус после отката:** изменения читового `-repick` и `-whosyourdaddy` отменены. В текущем игровом скрипте этих новых возможностей нет. Их описание ниже, а также файлы `tests/` и `tools/`, сохранены как материалы отменённой реализации. Тесты этой реализации не являются проверкой текущей карты; утилита добавления `ATwd` к ней не применена.

Справочник по реализациям в репозитории. **Наличие команды в старой версии не означает, что она доступна в текущей карте.** Версия и обработчик указаны в колонке «Откуда взят». У каждого источника своя строка.

**Пример последовательности:**

```text
-cheats bvo-rossoliny
-gold 10000
-level 25
-mana
-nc
-whosyourdaddy
-repick
```

Особенности `-repick` с читами: окно показывает героев, ещё не использовавшихся в матче, по восемь на странице. В каталог входят 32 исходных героя. Герой заменяется только после подтверждения выбора; «Отмена» сохраняет героя и золото. Ограничение на использованные типы сохраняет работу одноразовых систем инициализации героев. Без читов работают прежние условия, срок выбора и ограничение обычного `-repick`.

`-whosyourdaddy` использует отдельную пассивную способность `ATwd` на основе `Avul`. Выключение удаляет только `ATwd`, сохраняя обычную `Avul`. Смертельный удар наносится через `UnitDamageTarget`, чтобы сохранить атакующего и начисление убийства. Режим не меняет команды прямого удаления юнита. Объявления о читах видны всем игрокам, как у существующей консоли.

## Ошибки и особенности

| Проблема | Последствие | Откуда взят |
|---|---|---|
| `-playanimation` игнорирует число | Всегда запускается индекс 1. | 1.1c — `Test_Commands` |
| Справка содержит несуществующие обработчики `-unstuck`, `-text`, `-ca` | Текст помощи не подтверждает работоспособность команд. | 1.1c — справка и `GameCommands` |
| Справка камеры обещает предел 250 | Реальный верхний предел парсера — 200. | 1.1c — `GameCommands` |
| `-refresh` не вызывает сброс перезарядок | Восстанавливаются только здоровье и мана. | nw 5.0 — `TestSystem` |
| TestSystem и NZCP одновременно обрабатывают `-gold N` | В одиночной игре с активным паком возможны 2×N золота и N lumber. | nw 5.0 — оба обработчика `-gold` |
| `-copy` с отрицательным N; `-ritem 0` | Ошибочные условия выхода могут привести к бесконечному циклу. | nw 5.0 — NZCP |
| `-ms` без числа одновременно попадает в информационный и читовый обработчики | При активном паке может установить выбранному юниту скорость 0. | nw 5.0 — NZCP и обычный `-ms` |
| `-ms` без числа одновременно попадает в информационный и читовый обработчики | Аналогичный конфликт, значение аргумента преобразуется в 0. | 13.0 — JJ2197 и обычный `-ms` |
| `-loc`, `-regmin`, `-regmax` есть в помощи, но отсутствуют в рабочем диспетчере | Использовать `-reg` и два приказа в точку вместо обещанных отдельных команд. | 13.0 — JJ2197 |
| Помощь путает синтаксис `-spa`, `-charges`, `-area` | Использовать примеры из таблицы выше. | 13.0 — JJ2197 |
| Неверные длины `SubString` в старом блоке | Много команд `-D...` недостижимы. | 13.0 — `xXd` |
| `es.<команда>` вместо `es<команда>` | Привязывается ошибочная строка с лишней точкой. | 13.0 — FaiCp |

## Проверка текущих изменений

```powershell
python -m unittest discover -s cheats/tests -v
```

Тесты исполняют функции из актуального JASS-скрипта в модели событий Warcraft: персональный доступ, обычные условия repick, поздний выбор при пустом пуле, перенос предметов/зарядов, отмена, стоимость, сохранение ссылки участника дуэли, переключение режима бога и новые юниты. Отдельно проверяется добавление способности в бинарный `.w3a`.

При переносе скрипта в другую сборку карты нужно добавить **и** `ATwd` в `war3map.w3a`, а не только заменить `war3map.j`:

```powershell
python cheats/tools/add_god_ability.py input.w3a output.w3a
```

Утилита сохраняет существующие записи объектов и отказывается заменять уже существующий `ATwd`. У служебной способности обе расширенные строки описания завершаются `Updated by Rossoliny.`.
